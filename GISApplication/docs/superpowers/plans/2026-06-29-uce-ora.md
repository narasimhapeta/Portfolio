# UCE-ORA: Utility Corridor Encroachment & Outage Risk Analyzer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a .NET 8 Web API + ASP.NET MVC frontend that performs spatial buffer analysis against simulated Oncor power line data stored in Oracle XE, rendering results on a Leaflet.js map.

**Architecture:** A single solution with two projects — a Web API (`UCE-ORA.API`) handling all spatial logic via NetTopologySuite and an Oracle database, and an ASP.NET MVC frontend (`UCE-ORA.Web`) that calls the API via JavaScript fetch and renders GeoJSON overlays on a Leaflet map.

**Tech Stack:** .NET 8, Oracle XE 21c (Docker), Oracle.EntityFrameworkCore 8, NetTopologySuite 2.5, NetTopologySuite.IO.GeoJSON 4, Leaflet.js (CDN), HTML/CSS/Vanilla JS.

---

## Global Constraints

- .NET version: 8.0 (LTS)
- Oracle XE image: `container-registry.oracle.com/database/express:latest`
- Oracle port: 1521, SID: `XEPDB1`
- All coordinates in WGS84 (SRID 4326)
- Transmission lines stored as WKT strings (not Oracle SDO_GEOMETRY) to avoid SDO configuration overhead
- Buffer math: divide meters by 111,000 to convert to decimal degrees (acceptable for 6-hour demo scope)
- No authentication — table created manually via SQL*Plus; EF Core maps to it without running migrations
- Leaflet.js loaded from CDN, no npm/webpack

### Task 5: EF Core Data Layer (20 min)

**Goal:** `AppDbContext` and `TransmissionLineRepository` that read from the existing Oracle table using Entity Framework Core — no migrations, no schema changes.

- [ ] **Step 5.1 — Annotate `Models/TransmissionLine.cs` for EF Core**

  Create the model class with these four properties: `Id` (int), `Name` (string), `VoltageKv` (decimal), `LineWkt` (string).

  Apply these data annotations at the class level to tell EF Core the exact Oracle table and column names (Oracle stores identifiers uppercase by default):
  - `[Table("TRANSMISSION_LINES")]` on the class
  - `[Column("ID")]` on `Id`
  - `[Column("NAME")]` on `Name`
  - `[Column("VOLTAGE_KV")]` on `VoltageKv`
  - `[Column("LINE_WKT")]` on `LineWkt`
  - `[Key]` on `Id`

  > **Why annotations instead of Fluent API here:** keeps the model self-documenting and lets you skip a full `OnModelCreating` override.

- [ ] **Step 5.2 — Create `Data/AppDbContext.cs`**

  Create a class `AppDbContext` that extends `DbContext`. Add one property: `DbSet<TransmissionLine> TransmissionLines`. The constructor must accept `DbContextOptions<AppDbContext>` and pass it to the base constructor — this is the standard EF Core pattern.

  You do NOT need to override `OnModelCreating` — the `[Table]` and `[Column]` attributes on the model handle all mapping.

- [ ] **Step 5.3 — Configure connection string in `appsettings.json`**

  Add a `ConnectionStrings` section with key `"OracleDb"`. The value is:
  ```
  User Id=system;Password=OraPassword1;Data Source=localhost:1521/XEPDB1;
  ```

- [ ] **Step 5.4 — Register EF Core in `Program.cs`**

  Before `builder.Build()`, call `builder.Services.AddDbContext<AppDbContext>()` and configure it to use Oracle with the connection string named `"OracleDb"`. The Oracle EF Core provider's `UseOracle()` extension method accepts the connection string directly.

- [ ] **Step 5.5 — Create `Data/TransmissionLineRepository.cs`**

  Inject `AppDbContext` via constructor. Expose one async method `GetAllAsync()` that returns `await _context.TransmissionLines.ToListAsync()`.

  Register `TransmissionLineRepository` as a scoped service in `Program.cs`.

- [ ] **Step 5.6 — Quick smoke test (manual)**

  Temporarily add a minimal route in `Program.cs` that calls `GetAllAsync()` and returns the count as JSON. Run `dotnet run --project src/UCE-ORA.API`, navigate to `http://localhost:5000/test`, verify it returns `{"count": 8}`. Remove the test route afterward.

  > **Common failure at this step:** If EF Core throws `ORA-00942: table or view does not exist`, the table name casing is wrong. Verify the `[Table("TRANSMISSION_LINES")]` attribute uses all uppercase. Oracle is case-sensitive when names are quoted.

### Task 7: Implement SpatialAnalysisService (20 min)

**Goal:** All four tests pass with NTS-based spatial logic.

- [ ] **Step 7.1 — Create `Services/SpatialAnalysisService.cs`**

  The class holds a `GeometryFactory` initialized with `PrecisionModel` and SRID 4326 (WGS84). It exposes one public method:

  ```
  bool IsLineAtRisk(string lineWkt, double hazardLat, double hazardLng, double bufferMeters)
  ```

  The method must:
  1. Guard against null/empty `lineWkt` — throw `ArgumentException`.
  2. Parse the WKT string into a `Geometry` using `WKTReader`.
  3. Create a hazard `Point` using `Coordinate(hazardLng, hazardLat)` — **longitude first** (GIS convention).
  4. Buffer the hazard point by `bufferMeters / 111000.0` to convert meters to approximate decimal degrees.
  5. Return `line.Intersects(bufferZone)`.

- [ ] **Step 7.2 — Register `SpatialAnalysisService` in `Program.cs`**

  Add as a scoped service.

### Task 12: Implement `wwwroot/js/map.js` (20 min)

**Goal:** Map initializes on Dallas, loads all lines, and re-renders hazard analysis on button click.

- [ ] **Step 12.1 — Create `wwwroot/js/map.js`**

  The file must do the following in order:

  **Initialize Leaflet map:**
  - Create map centered on Dallas: `[32.7767, -96.7970]`, zoom level 10.
  - Add OpenStreetMap tile layer.

  **Declare module-level layer variables:**
  - `let linesLayer = null` — holds the GeoJSON layer for all lines.
  - `let hazardCircle = null` — holds the risk circle marker.
  - `let threatenedLayer = null` — holds highlighted threatened lines.

  **Load all transmission lines on page load (`DOMContentLoaded`):**
  - Fetch `http://localhost:5000/api/infrastructure/lines`.
  - Parse the JSON as a GeoJSON FeatureCollection.
  - Add it to the map using `L.geoJSON()` with a blue polyline style.
  - Store it in `linesLayer`. Fit the map bounds to the lines layer.

  **Wire up the Analyze button (`analyzeBtn` click handler):**
  1. Read `lat`, `lng`, `radius` from the input fields.
  2. Remove old `hazardCircle` and `threatenedLayer` from the map if they exist.
  3. Draw a yellow `L.circle` at `[lat, lng]` with the radius in meters and add to map.
  4. Fetch `http://localhost:5000/api/infrastructure/risk-assessment?lat={lat}&lng={lng}&radiusMeters={radius}`.
  5. Parse the response JSON.
  6. If `TotalThreatenedLines > 0`:
     - Add a red GeoJSON layer using the threatened lines' WKT converted to GeoJSON (hint: each `ThreatenedLine.LineWkt` needs to be parsed — you can do this server-side or client-side using a tiny WKT→GeoJSON converter; the simplest approach is to have the API return GeoJSON geometries directly in `ThreatenedLines` by also serializing each line's geometry there).

  7. If `TotalThreatenedLines === 0`:
     - Update `results` div with: `✓ No lines threatened within ${radius}m`.

  > **Tip on the WKT→GeoJSON gap:** The cleanest fix is to modify `RiskResult.cs` to add a `ThreatenedLinesGeoJson` string property (serialized FeatureCollection) and have the controller build it using `GeoJsonWriter` — same logic as the `/lines` endpoint. ## Risk Mitigations

| Risk | Mitigation |
|------|-----------|
| Oracle Docker pull takes too long | Do Task 2 in a parallel terminal while it downloads |
| EF Core `ORA-00942: table or view does not exist` | Verify `[Table("TRANSMISSION_LINES")]` uses all uppercase — Oracle is case-sensitive when names are quoted |
| EF Core `ORA-01017: invalid username/password` | Double-check connection string in `appsettings.json` matches the Docker `-e ORACLE_PWD` value |
| CORS blocks browser fetch | Apply CORS policy in `Program.cs` before `app.MapControllers()` |
| WKT→GeoJSON mismatch in frontend | Return GeoJSON FeatureCollection string directly from the API — avoid client-side WKT parsing |
| Leaflet map height is 0 | Confirm `html, body { height: 100%; }` and `#map { height: 100vh; }` are set |
